# 第7段階：副詞的分詞の区別と候補比較

> **資料の優先順位：本監査ではWallaceを主資料とする。** 本書の分類と新約聖書の用例を基準にし、Smythは必要な場合に限って一般的なギリシャ語文法の補助照合に用いる。Smythの分類をWallaceの分類に代用したり、Wallaceと異なる場合に無注記で混在させたりしない。

## 監査の結論

主たる照合対象はWallace, *Greek Grammar Beyond the Basics* §27.B（ExSyn pp.623–645）および *The Basics of New Testament Syntax* の分詞章である。Wallaceの体系では、副詞的分詞の時間・様態・手段・原因・条件・譲歩・目的・結果が区別され、付帯状況などは別項目として扱われる。Smyth §§2060–2069は、必要な場合の一般文法上の補助照合に限る。

副詞的分詞は、分詞の形だけで「時間」「理由」「条件」「譲歩」などの意味が自動的に決まるわけではない。Smyth §§2060–2069 は、時間・様態・手段・原因・目的・譲歩・条件・付帯状況などの関係は文脈から生じ、同じ分詞を複数の関係で理解できる場合があると明記する。Bible.orgの分詞解説も、時制形・語順・文脈・動詞の語彙的意味・意味状況を合わせて候補を絞ると説明する。

したがって、現行レジストリの説明にある「形だけで機械的に決めない」「文脈で判断する」という注意は方向として正しい。ただし、これだけでは読者に何を根拠に見分けるかが伝わりにくい。比較文では、各候補の意味と、本文から確認する具体的な問いを併記する。

## 1. 候補比較の基準

| 候補 | 読者向けの問い | 本文で確かめる手掛かり |
|---|---|---|
| 時間 | 主動詞の出来事と、いつ起きたか／どの順で起きたか | 分詞と主動詞の相対的な時間関係、文脈の時間表現 |
| 理由・原因 | なぜ主動詞の出来事が起きたか | 分詞の内容が主動詞の理由として自然か、因果関係が文脈にあるか |
| 条件 | どの条件が満たされれば主動詞が成り立つか | 仮定・一般条件・帰結の関係が成立するか |
| 譲歩 | どの事情があるのに、主動詞が成り立つのか | 分詞の内容と主動詞の間に予想に反する対照があるか |
| 様態 | 主動詞の動作がどのように行われたか | 分詞が動作のあり方を描写しているか |
| 手段 | 何をすることによって主動詞を実現したか | 分詞の行為が主動詞を実現する方法・手段として働くか |
| 付帯状況 | 主動詞の動作と並んで、どの動作が起きたか | 分詞が単なる時・理由などでは説明しにくい、主動詞と連動する動作を表すか |
| 目的・結果 | 主動詞の行為が何を目指すか／何を生じさせるか | 目的を示す意図的関係か、行為から生じた結果か |

この表は読者向けの検討用基準であり、個々の箇所に対する自動判定アルゴリズムではない。形態・語順は証拠の一部であって、それだけでラベルを決めない。

## 2. 重要な隣接候補

### 時間 vs 理由

どちらも「〜して」と訳せることがある。

- **時間**：「〜したとき／〜してから」として、出来事の時間関係を述べる。
- **理由**：「〜なので／〜したため」として、主動詞の出来事の理由を述べる。

比較表示案：
> **時間の読み**では、分詞は主動詞の出来事がいつ起きたかを示します。**理由の読み**では、分詞の内容が主動詞の出来事を起こした理由を示します。訳語だけで決めず、前後の文脈に時間関係と因果関係のどちらがあるかを確かめます。

### 理由 vs 譲歩

- **理由**：分詞の内容が主動詞を支える理由になる。
- **譲歩**：分詞の内容があるにもかかわらず、主動詞の内容が成り立つ。

比較表示案：
> **理由の読み**では「〜なので、主動詞が起きた」と理解します。**譲歩の読み**では「〜であるのに、主動詞が成り立つ」と理解します。分詞と主動詞が因果関係にあるのか、予想に反する対照にあるのかを確認します。

### 様態 vs 手段

- **様態**：動作がどのように行われるか。
- **手段**：何をすることによって動作が実現するか。

比較表示案：
> **様態の読み**は動作のあり方を描きます。**手段の読み**は、分詞の行為が主動詞を実現する方法を示します。「〜して」と訳せるかどうかではなく、分詞が動作を描写しているのか、実現手段を示しているのかを確認します。

### 時間 vs 付帯状況

付帯状況は、単に「同じ時間に起きた動作」と同義ではない。主動詞と連動する別の動作として解釈できるかを確認する。Bible.orgは、付帯状況とする前に、時間など通常の副詞用法として自然に読めないか検討するよう促している。付帯状況の判定は学者間でも議論があり、曖昧な箇所を安易に断定しない。

比較表示案：
> **時間の読み**では、分詞は主動詞の出来事の時点・順序を示します。**付帯状況の読み**では、分詞は主動詞と連動する動作を表し、訳では独立した動詞のように続けられることがあります。付帯状況とするには、単なる時間関係以上の根拠が必要です。

### 目的 vs 結果

現行ラベル「目的・結果」は一つのラベルにまとめられているが、説明内では意味を分けている。実際に両方が候補として競合する箇所では、区別を比較表示に出す価値がある。

- **目的**：「〜するために」。行為が目指すもの。
- **結果**：「その結果〜する／〜となる」。行為によって生じること。

未来分詞は目的の読みを支える手掛かりになり得るが、形態だけで目的と断定しない。構文と文脈の確認を要する。

## 3. 属格絶対分詞との関係

属格絶対分詞は、主節の主要な構文関係に直接組み込まれない属格の名詞・代名詞と属格分詞からなる構文である。一方、「時間」「理由」「条件」「譲歩」「付帯状況」は、その構文が主節とどう意味的に結びつくかを表す関係である。つまり、**属格絶対**は主に構文上の形、**時間・理由など**は意味上の関係であり、同じ階層の排他的な選択肢として並べるべきではない。

したがって、同一トークンで `participle.genitive_absolute` と `participle.adverbial_temporal` などが同時に候補になるデータ設計の場合、UIは「構文上の特徴」と「主節との意味関係」を別の軸として説明する。実際のデータが別の排他的分類方式を採る場合は、まずスキーマを確認してから実装する。

## 4. すべての箇所に適用する際の要件

1. `alternatives` 配列は分類間の関連性を示すだけで、実トークンに同時候補がある証拠ではない。
2. 比較UIは同じトークンについて解析器が実際に出した候補に限って生成する。
3. 候補比較では、各候補の説明だけでなく「この箇所で何が異なるのか」を示す。
4. 文脈・形態・語順・語彙的意味のどの手掛かりを使ったかを確認できない場合は、根拠があるように装った説明を生成しない。
5. 解析器が一候補を選んでいる場合に、単にレジストリの関連候補を追加して「複数候補」と表示しない。
6. 確度スコアを統計的に校正された確率であるかのように表示しない。
7. 「判定不能」を表示する場合は、分類名だけでなく、どの根拠が不足しているのかを明示する。
