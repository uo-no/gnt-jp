- 対象: `public/core/syntax-analyzer.js`（main）、`public/assets/data/syntax-registry.json`

## 1. `article.colwell`: 説明の誤解リスクをコードで確認

### 実装の動作

`CheckEvaluator.register('colwell_subject_article', ...)` は概ね次の条件を調べている。

1. head が主格である。
2. 節内に `εἰμί` または `γίνομαι` の定形動詞がある。
3. コプラより前に、head 以外の主格名詞または形容詞がある。
4. そのトークン直前が冠詞ではない。

これは「コルウェルの条件に関連する構文候補」を拾うためのヒューリスティックとしては理解できるが、**このコード自体が述語主格の定性や意味、あるいは主語・述語の関係を確定しているわけではない**。一方、コメントには「冠詞は主語標識」と書かれ、レジストリの label も「コルウェル構文（主語標識）」となっている。この説明は実装の検出範囲を越えた断定に見える。

### 提案

- ユーザー向け説明は第2回メモの候補に差し替える。
- 表示名を「コルウェル規則に関係する構文」等へ変更するかは、242件全体の命名方針と合わせて決める。
- コメントの「冠詞は主語標識」という断定も別のコード修正タスクで見直す。
- 今回は実装ロジックに手を加えない。実際の回帰例と誤検出例を揃えた後に、検出条件の改善を独立に検討する。

## 2. `prep_object_case()`: 検出関数の限界を明示

実装は対象前置詞の次から最大6トークンを順に走査し、最初に形態解析上の格が得られたトークンが指定格かを返す。

これは単純で高速だが、関数単体では以下を保証しない。

- その名詞句が構文上、対象前置詞の目的語であること
- 節境界を越えていないこと
- 走査中に別の名詞句があっても、対象前置詞に結びつく句を正しく選べていること

したがって、レジストリ説明の「前置詞が属格／与格／対格を支配する」と、実装が観察している「後方の最初の格付きトークン」は同義ではない。これは説明文の言い換えだけでは直らない、検出精度に関わる別の論点である。

### 提案

- 現時点では格支配の定義を短く保ち、「この構文候補として検出された」ことを文法的確定判定と同一視しない。
- 次のロジック監査では、対象前置詞と目的語句の結びつき、句境界、節境界を扱える既存データ・ヘルパーがあるかを確認する。
- 既存回帰テスト `scripts/genitive-regression-test.cjs` の3例（MRK 1:10、MAT 3:11、MAT 4:12）を保持し、追加の曖昧な例・否定例がないままロジックを変更しない。

## 3. 前置詞の語彙リストについて

レジストリの3型（固有前置詞＋属格／与格／対格）は、同じ固有前置詞17語のリストと格判定を組み合わせている。よって、リスト全体が「各格を取る前置詞の一覧」という意味ではなく、固有前置詞候補の集合であり、実際の出現箇所の格を別条件で判定する構造と読める。

この設計意図自体は成立しうるが、検出関数の限界があるため、実際の目的語の格を確実に取得しているとは言い切れない。説明文に17語のリストを直接埋め込むより、各型の定義は「固有前置詞がその格の名詞句を伴う構文」とし、語彙リストは実装・回帰テスト側で管理する方が明瞭。
