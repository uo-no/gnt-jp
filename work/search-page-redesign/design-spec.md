> 対象: `public/search-tool.html`
> フェーズ: Phase A（現状調査）＋ Phase B（情報設計）＋ Phase C（ビジュアル設計）＋ Phase D（比較設計監査）
> 状態: DESIGN — 実装未開始
> 制約: 検索ロジック・データ構造・URL仕様・JS関数シグネチャを変更しない

## 1. 現状の問題点と原因

### 1-1. タイポグラフィの崩壊

現在のファイルには tokens.css の6段階スケール外のフォントサイズが約15種類存在する。

```
確認値: 0.52, 0.55, 0.58, 0.60, 0.62, 0.65, 0.68, 0.72, 0.78,
        0.82, 0.88, 0.9, 1.05, 1.15, 1.35rem (すべてインライン定義)
トークンスケール: 0.75, 0.9, 1.0, 1.25, 1.5, 2.0rem
```

**原因**: 各コンポーネントが独立して追加された際にトークンを参照せず直接値を書いた。
**影響**: 階層感がなく「情報密度が高い=雑然」に見える。

### 1-2. 検索レイヤーセクションの視覚的過負荷

各レイヤー行が名前・説明・チェックボックス・サブコントロールを含む。
説明テキストが常時表示されているため、セクション全体の高さが必要以上に大きい。

```
現状: レイヤー行1つ ≈ 60px (name + desc + padding)
問題: 4つのレイヤー = 約240px + proximity sub (100px) or morph sub (200px以上)
```

**原因**: 学習コスト削減のための説明テキストが常時表示されている。
**影響**: サイドバーが長くなり、履歴や戻るボタンが画面外に出る。

### 1-3. 4色のレイヤーカラーシステムが UI を染める

lemma（青）、phrase（緑）、prox（オレンジ）、morph（紫）の4色が、
チェックボックス・バッジ・サブコントロール・スニペット強調まで使われている。

**原因**: レイヤー識別のために色をつけた設計が、UI全体に伝播している。
**影響**: アクセント色 `--accent` が埋没し、ブランドの一貫性が失われる。

### 1-4. 中間ブレークポイント (680px–860px) の未解決

680px 超では2カラム表示だが、860px 未満では縦積みに変わる。
この「縦積みになるが左パネルが全幅」の状態は、スクロールが増え
モバイルでもデスクトップでもない中途半端なレイアウトになる。

**原因**: 680px/860px の2つのブレークポイントが異なるパターンを担当。
**影響**: 縦向きタブレットや大型スマートフォンで使いにくい。

### 1-5. ヒットカード内の情報階層の逆転

各ヒットカードに「日本語訳（非同期ロード）」と「ギリシャ語スニペット」が並ぶが、
スニペットが先に表示され、訳は `visible` クラスが追加されるまで hidden になる。

**原因**: 非同期フェッチのため表示順が確定しない。ローディング中の「読み込み中…」テキストが目立つ。
**影響**: 読者が見たいのは訳文なのに、最初にギリシャ語スニペットが見える。

### 1-6. Discovery Lobby の孤立感

空状態の「今日のみことば」カードが結果エリアの中央に浮いているが、
サイドバーの検索入力との関係が視覚的につながっていない。

**原因**: サイドバーとメインエリアが視覚的に独立していて、
検索入力が「この画面で何ができるか」を伝えていない。

### 1-7. 戻るナビゲーションの二重実装

`_searchGoBack()` 呼び出し箇所が2か所ある。

- サイドバー内ヘッダー（デスクトップ）: `button` in `.search-panel`
- `#mn-back-bar`（モバイル専用スティッキー行）: `display:none` → `display:flex` at ≤680px

実装は同一だが DOM が2つ存在し、スタイルも別に書かれている。

## 3. 新しい情報設計

### 3-1. 情報の優先順位

```
1. 聖書テキスト（ヒットカードの訳文 + ギリシャ語）
2. 検索アクション（入力欄 + 基本モード）
3. 結果サマリー（件数 + 分布）
4. 高度なオプション（レイヤー拡張 + 絞り込み）
5. 探索支援（概念インサイト + パターン提案）
```

### 3-2. セクション順序とグルーピング

#### サイドバー（検索コントロール）

```
[戻るナビゲーション]           ← 最小化。1行のみ
[ページタイトル]               ← "聖書原文検索"
[インデックス状態]             ← 準備中のみ表示。完了後フェード
─────────────────────
[検索入力 + サジェスト]        ← 最も目立つ要素
─────────────────────
[検索モード]                   ← デフォルト: lemmaのみON
  lemma（常時表示、チェック付き）
  [▸ 詳細オプション]            ← collapsible
    近接検索 + スライダー
    フレーズ検索
    品詞・語形絞り込み
─────────────────────
[アクティブフィルター]          ← SQS pills（条件あり時のみ）
─────────────────────
[検索履歴]                     ← 検索済み時のみ
```

#### 結果エリア

```
[空状態: Discovery Lobby]
  ↓ 検索実行
[ローディング]
  ↓
[結果ヘッダー: クエリ + 件数 + バッジ]
[概念インサイト（発火時のみ）]
  ─────────────────────
  [ヒットカード × N]            ← 日本語訳 → ギリシャ語 の順
    [書物フィルター行]           ← 書物分布（件数多い時）
    [さらに表示ボタン]           ← 8件超時
  ─────────────────────
  [構文パターンパネル]          ← 構文検索発火時
  [パターン探索提案]            ← 結果末尾
```

### 3-3. レイヤー選択の再設計

**現在**: 4つのレイヤーが常時展開され、各行に名前+説明が表示される
**新設計**: lemmaを常時表示。残り3つを「詳細オプション」として折りたたむ

**理由**:
- lemmaは「語根検索」の基本機能で、ほぼ常時使う
- prox/phrase/morphは上級オプション
- 説明テキストはアイコンのtitleやtooltipで代替

折りたたみ開閉の仕様:
- `<details>` 要素を活用（既存の `.advanced-layers` パターンを流用）
- 開いていてもclose後もチェック状態を維持する
- アクティブレイヤーが1つでもあれば「詳細オプション（N個選択中）」と表示

## 6. 余白・幅・文字階層・色・境界線の設計ルール

### 6-1. タイポグラフィ（全トークン参照）

| 用途 | トークン | 値 |
|------|---------|-----|
| ページタイトル | `--text-body-lg` | 1rem |
| セクションラベル (CAPS) | `--text-caption` | 0.75rem |
| レイヤー名 | `--text-body` | 0.9rem |
| レイヤー説明（廃止→title属性へ） | — | — |
| 検索入力 | `--text-body-lg` | 1rem |
| 候補サジェスト | `--text-body` | 0.9rem |
| ヒット参照ラベル | `--text-caption` | 0.75rem |
| ヒット訳文 | `--text-body` | 0.9rem |
| ギリシャ語スニペット | `--text-body-lg` + Gentium Plus | 1rem |
| 結果件数 | `--text-caption` | 0.75rem |
| バッジテキスト | `--text-caption` | 0.75rem |

`0.52rem` `0.60rem` `0.68rem` `0.72rem` `0.82rem` `1.05rem` `1.35rem` 等のスケール外値はすべて上記に置換する。

### 6-2. 余白（スペーストークン）

| 箇所 | トークン |
|------|---------|
| サイドバー外側パディング | `--space-lg` (24px) 上下、`--space-md` (16px) 左右 |
| セクション間 | `--space-xl` (32px) |
| グループ内要素間 | `--space-sm` (8px) |
| レイヤー行内パディング | `--space-sm` `--space-md` (10px 12px) |
| ヒットカード外側パディング | `--space-md` (14px 16px) |
| ヒットカード間ギャップ | `--space-sm` (8px) |
| 結果パネルパディング | `--space-xl` `--space-lg` (28px 32px) |

### 6-3. 色の使い方

**アクセントは1種類**: `--accent` (#2c4f34) のみ。

| 用途 | 値 |
|------|-----|
| 検索入力フォーカスリング | `--accent-light` |
| 活性レイヤー行の左ボーダー | `--accent-mid` |
| 「本文で読む」ボタン | `--accent` + 白文字 |
| 参照ラベル（強調） | `--accent` |
| 分布バーフィル | `--accent` opacity 0.55 |

**レイヤーカラー（lemma/prox/phrase/morph）の役割を限定**:
- UIコントロール側（チェックボックス、バッジ背景、サブコントロール枠）: 廃止 → `--accent` 系に統一
- スニペット内ハイライト: **維持**（`.hl-lemma` `.hl-phrase` `.hl-prox-w1` 等は残す）

理由: スニペット内の強調は「どのレイヤーでマッチしたか」の情報であり意味がある。UIコントロールの4色は情報を持たない装飾。

### 6-4. 境界線

| 箇所 | スタイル |
|------|---------|
| サイドバー右ボーダー | `1px solid var(--border)` |
| セクション区切り | `border-top: 1px solid var(--border)` |
| ヒットカード | `border: 1px solid var(--border)` |
| ヒットカード hover | `border-color: var(--border-strong)` |
| 検索入力 | `border: 1px solid var(--border)` → focus: `var(--accent)` |
| レイヤー行（非活性） | border なし、hover: `background: var(--bg-panel)` |
| レイヤー行（活性） | `border-left: 2px solid var(--accent-mid)` |

「カードを重ねる」のではなく「境界線で区切る」方向に統一。角丸・影は最小化。

### 6-5. 角丸

| 箇所 | トークン |
|------|---------|
| 検索入力 | `--radius-m` (8px) |
| ヒットカード | `--radius-m` (8px) |
| バッジ・チップ | `--radius-pill` |
| モバイルボトムドロワー | 18px 18px 0 0（現行維持） |
| FABボタン | `--radius-pill` |

## 7. 検索操作と選択状態の仕様

### 7-1. レイヤー選択状態

| 状態 | 表示 |
|------|------|
| 非活性 | 背景なし、テキスト `--text-sub` |
| hover | 背景 `--bg-panel` |
| 活性 | 左ボーダー `2px solid var(--accent-mid)` + チェックマーク `--accent` |
| 詳細オプション内・活性 | 上記に加え詳細オプションヘッダーに「(N個選択中)」バッジ |

### 7-2. 検索ボタンの表示条件

- 入力欄内の虫眼鏡アイコンは常時表示
- `Enter` キーまたはアイコンクリックで検索実行
- ローディング中は虫眼鏡を X（キャンセル）に変える（現行実装があれば維持）

### 7-3. インデックスロード状態

- 準備中: `#idx-pill` を `height: auto` で表示（現行: `2.5rem` 固定）
- 完了後: `opacity: 0` でフェードアウト（現行維持）
- ただし「準備中」テキストは検索入力より上に表示しない

### 7-4. サジェストドロップダウン

現行仕様を維持。変更なし。

### 7-5. Proximity スライダー + プリセット

詳細オプション内のサブコントロールとして維持。
スライダーのスタイルのみトークン参照に統一（現行は `var(--prox)` → `var(--accent)` へ）。

### 7-6. Morph チップ

詳細オプション内のサブコントロールとして維持。
チップの色は `var(--morph)` 系 → `var(--accent)` 系へ統一。
選択中: `background: var(--accent)` + 白文字。

### 7-7. SQS フィルターバー

現行仕様を維持。詳細オプションセクションの下に表示（現行と同位置）。

## 8. ヒットカードの仕様

### 現行の問題

訳文が非同期ロードのため「読み込み中…」テキストが先に出る。
ギリシャ語スニペットが先に DOM に存在し、訳文より先に見える。

### 新設計

```html
<div class="hit-card">
  <!-- ヘッダー -->
  <div class="hit-header">
    <span class="hit-ref">ヨハネ3章16節</span>    <!-- accent color -->
    <span class="corpus-badge">LXX</span>          <!-- LXXのみ表示 -->
    <div class="hit-badges-subtle">                <!-- 右寄せ、subtle -->
      <span class="ht-badge lemma">語根</span>
    </div>
  </div>

  <!-- 本文: 訳文が主役 -->
  <div class="hit-body">
    <div class="hit-trans-row">
      <p class="hit-trans-text">...</p>            <!-- 非同期。表示されたら primary -->
      <span class="hit-trans-loading">...</span>   <!-- ロード中のみ表示 -->
    </div>
    <!-- ギリシャ語: 折りたたみ -->
    <details class="hit-greek-details">
      <summary>ギリシャ語原文を見る</summary>
      <div class="hit-snippet">...</div>           <!-- Gentium Plus -->
    </details>
  </div>

  <!-- フッター -->
  <div class="hit-footer">
    <a class="hit-open-btn-lg" href="...">本文で読む</a>
  </div>
</div>
```

**変更点**:
- ギリシャ語スニペットを `<details>` に包む
- 訳文を `<p>` タグへ変更（意味論的に正しい）
- `hit-trans-loading` はロード完了後 `display:none`

**実装ガイド**: `_buildUnifiedCard()` の HTML テンプレート文字列を修正する。
ロジック（anchorGi, entry, hitTypes, 強調クラス）は変更しない。

## 14. 設計上の判断理由と未解決事項

### 判断理由

**A. レイヤーカラーをスニペット強調に限定する理由**

検索アクション（チェックボックスON/OFF）に4色は過剰。
スニペット内強調は「どのルールでマッチしたか」という情報量があるが、
チェックボックスが青い/緑いことに情報量はない。
→ UIコントロールは `--accent` 単色に統一し、認知負荷を下げる。

**B. ギリシャ語スニペットをデフォルト折りたたみにする理由**

このアプリの主役は「聖書を読む体験」（First Principle）。
検索結果で見たいのは「この節に該当の語が出てくる」ことの確認であり、
精読はヒットカードからリーダーへ移動して行う。
ギリシャ語スニペットは研究者向けの補足であり、折りたたみが適切。
→ 訳文を主役にする。

**C. 860px ブレークポイントを廃止する理由**

縦積みにすると「左パネルが全幅で長い → 下にスクロールして結果を見る」という
動線が生まれる。スクロール量が増え、「戻るボタンが見えなくなる」など
ナビゲーション問題が発生する。
→ 680px 以下はドロワー、それ以上は常に横並びとする。

**D. インデックスロード状態を入力欄の下に置かない理由**

現行は `idx-status` がインデックス状態を表示するが、高さ固定 `2.5rem`
で検索欄が下に押し出されている。視覚的ジャンプが起きる。
→ 状態表示を検索入力の上（ページタイトル直下）に移動し、
フェードアウトで消えても検索欄の位置が変わらないようにする。

### 未解決事項

| 項目 | 内容 | 必要な判断 |
|------|------|-----------|
| U-1 | Concept Insight の展開デフォルト状態 | 初回は折りたたみが良いか、自動展開が良いか |
| U-2 | Proximity スライダーの距離デフォルト | ±5語が適切かどうか（現行維持で問題ないなら N/A） |
| U-3 | ヒットカードのギリシャ語デフォルト状態 | 折りたたみデフォルトは研究者にとって不便な可能性あり |
| U-4 | 書物分布パネルの位置 | 結果末尾（現行）vs 結果ヘッダー下 |
| U-5 | 構文パターンパネルのトリガー | `#syntax-panel` はどういう条件で表示されるか（JSを追跡していない） |

U-3 については、`localStorage` で状態を保持する実装（検索ツールがONなら以降は展開）
という選択肢もある。これはロジック変更になるため今 Phase では保留とする。

### D-4. タスク別 ギリシャ語スニペット表示の優先順位

比較調査と タスク分析から、「ギリシャ語スニペット折りたたみデフォルト一律適用」は
**Task A のみ適切で、Task B–D では逆効果**であることが確認できた。

| タスク | クエリ種別 | スニペット初期表示 | 根拠 |
|--------|-----------|-----------------|------|
| A: 日本語キーワード | 日本語入力 | **折りたたみ** | 訳文確認が目的。スニペットは補足 |
| B: ギリシャ語 lemma | ギリシャ語入力 | **展開** | 語形・強調が検索の主目的 |
| C: 形態論条件 | morphフィルター | **展開** | 語形の確認が検索の目的 |
| D: 近接検索 | 複数語 | **展開** | 二語の位置関係可視化が価値 |
| E: 文脈確認 | — | どちらでもよい | リーダー移動で完了 |
| F: 研究深化 | — | タスクA–Dに従う | 上流のタスクに依存 |

**実装方針**: クエリ種別 (`detectQueryType()` の返り値) によって
`_buildUnifiedCard()` の初期表示を切り替える。

```
detectQueryType('愛')         → 'japanese'  → スニペット折りたたみ
detectQueryType('ἀγαπάω')    → 'greek'     → スニペット展開
detectQueryType('G25')        → 'strong'    → スニペット展開
detectQueryType('text')       → 'text'      → スニペット折りたたみ（英語テキスト）
morph レイヤー発火時           → 展開（morphビルダー選択時）
```

`detectQueryType()` は既存関数であり、変更不要。
`_buildUnifiedCard()` の HTML テンプレートで `open` 属性の有無を切り替えるだけ。

### E-7. U-8 採用理由と却下理由

#### 採用: X＋Y 独自案

| 継承元 | 採用する要素 | 採用理由 |
|--------|------------|---------|
| 方向 X | リスト型結果（カード廃止）、タイポグラフィ主体の階層表現 | 本文・訳文・原語情報をカードの装飾より文字サイズと余白で読ませる |
| 方向 X | 区切り線のみのシンプルなアイテム分割 | 情報密度が高くても「読む」リズムが生まれる |
| 方向 Y | 検索入力を画面の最上位に配置（サイドバー廃止） | 「検索ツールである」という目的が即座に伝わる |
| 方向 Y | 詳細オプションは入力欄直下に展開するパネル | 検索条件と入力欄の関係が視覚的に明確 |
| 方向 Z | 「本文で読む」ボタンの視認性を高い優先度で維持 | 検索結果から読書への導線を断たない |
| 方向 Z | 訳文の可読性（Noto Serif JP、ゆったりした行間） | 検索結果でも「読む」体験を支える |

#### 却下: 方向 X 単独

`tokens.css` を前提としたサイドバー構造をどこまで残すか曖昧になる。
サイドバーを「細くして残す」だけでは Y の「検索ファースト」という目標を達成できない。

#### 却下: 方向 Y 単独

モダン検索 UI (Perplexity的) に近づきすぎ、ギリシャ語テキストの扱いが
日本語 UI に埋没する。原語研究ツールとしての独自性が失われる。

#### 却下: 方向 Z 単独

サイドバーを維持するため既存デザインとの差別化が小さく、
「ゼロベースで再設計する」という原則に応えられない。

### E-8. 独自デザインシステム
