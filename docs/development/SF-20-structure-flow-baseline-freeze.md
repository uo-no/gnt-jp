# SF-20 Structure Flow 基準確定（Baseline Freeze）

作成: 2026-08-12
State: BASELINE FROZEN（明示指示なしに変更しない）
根拠: SF-19 実装 ＋ 実 Chrome 7ケース UX 検証（本ターン）／総合判定 **PASS WITH MINOR FIXES**
実装位置（変更時はここを確認）: `public/index.html` の `_sfRelationModel` / `_sfRenderRelationFlow`（縦型）＋ `.sf-l1`/`.sf-verb-wrap`/`.sf-branches`/`.sf-branch` CSS。

> 本書は現在の Structure Flow（FLOW 構文表示）の基本 UI 構造を「現時点の確定基準」として固定する。
> 目的は「さらに改善する」ことではなく、**今後の実装で不用意に崩れないようにする**こと。

---

## 1. 確定した基本 UI 原則（読む順序）

```
主語 ── 動詞
          │
       ┌──┴──┐
       ↓     ↓
     関係A  関係B
```

- **主語＋動詞を最初に読む** → その後 **動詞に関係する要素を枝として読む**。
- これは「構文解析結果を見せる UI」ではなく **文の構造を読みやすくした表示**。

## 2. 明示指示なしに変更しないもの（FROZEN）

- 第1層を **主語＋動詞** とする構造。
- 第1層の **横並び**。
- 第1層を **最初に読ませる**（常にコンテンツ最上段）構造。
- **動詞を枝の起点**とする構造。
- 関係要素を **枝として下に展開**する構造。
- **横 overflow 回避**（幅は container 頭打ち・縦折返し）。
- mobile で **目的語・間接目的語等を無理に横一列へ戻さない**（縦維持）。
- **「構文解析図」らしさを増やさない**（ラベル・線を増やして情報量を増やすことを改善としない）。

特に次の独断判断を禁止する:
- 「長いから別レイアウトにする」
- 「情報が多いから構文木に戻す」
- 「枝が多いから第1層を変更する」

## 3. 実 Chrome 7ケース UX 検証（確定記録）

全ケース: 第1層＝主語＋動詞（横並び・常に最上）／動詞から下方向へ枝／横 overflow なし（mobile も）。

| Case | 例 | 1秒で主語+動詞 | 枝の関係理解 | 文構造に見える |
|---|---|---|---|---|
| C1 目的語のみ | 受ける(s,v,o) | Yes | Yes | Yes |
| C2 間接目的語 | 答える(io,s,+従属副詞) | Yes | Partial | Partial |
| C3 目的+間接(基準) | 与える(o+io) | Yes | Yes | Yes |
| C4 修飾要素 | 知る(s,o,adv) | Yes | Yes | Yes |
| C5 複数修飾 | 来る(s,v,adv×3) | Yes | Partial | Partial |
| C6 従属節 | できる(s,v,目的語節,adv) | Yes | Partial | Partial |
| C7 長い文 | 倒れる(6構成) | Yes | Partial | Partial |

総合判定: **PASS WITH MINOR FIXES**（基本設計は7ケース全てで成立・破綻なし。局所課題は §4 のみ）。

## 4. 既知の問題（現時点では必須修正でない・今回実装しない）

**長い従属節の枝チップ（C2/C5/C6/C7）**
- 従属節全体が1つの枝チップとして連結表示され、ラベルが長く・折返しが増え・band が縦に伸び・複雑文で list/diagram 感が増す。
- ただし: 横 overflow なし／第1層は崩れない／mobile も破綻しない／基本構造は成立。
- ⇒ **必須修正ではない。今回は実装しない**。将来候補は §6。

## 5. 自動詞の frame=0（バグではない）

- C5/C7 は自動詞で frame 項が無く、枝が neutral になる。
- これは **Lowfat データ構造に忠実な正しい挙動**。**推論で人工的な項を追加しない**（L-0）。

## 6. 将来の改善候補（記録のみ・今回は実装しない）

- 長い従属節枝の **折りたたみ**。
- 長い従属節枝の **要約表示（先頭数語＋…）**。

これらは基本構造（§1/§2）を変えない範囲での局所改善候補として記録する。実装は別途明示指示があってから。

## 7. 変更時の手続き（軽い FROZEN 運用）

§2 の項目を変更する必要が生じた場合は、CLAUDE.md の FROZEN 手続きに準じ、(1) 変更理由、(2) 影響範囲、(3) 7ケース相当の再検証、を伴わせる。独断で基本構造を再設計しない。
