# SF-15 Structure Flow Layout 再設計（design only・コード変更なし）

作成: 2026-08-12
State: DESIGN AUDIT（実装しない）
前提: SF-12（role 統合）, [SF-13](./SF-13-frame-connector-design-audit.md), [SF-14](./SF-14-frame-connector-implementation-structure.md)
**前提変更**: Structure Flow は **structural order（原文順）維持を必須としない**。語順は別の「Word Order フロー」が担うため、Structure Flow の横軸は再設計してよい。

> 中心の問い: **「Structure Flow の横方向を何の軸にすべきか？」** 原文順である必要はない。
> focus とその構造関係を最も読みやすくする軸を設計する。

## SF-15-A: 現状（SF-14）の問題

SF-14 は横軸に structural order（原文順）を固定していた。John 6:37 δίδωσίν の原文順は **O-V-IO-S**:
```
目的語      動詞★       間接目的語     主語
〜するもの → 与える★ →   私     →   ［冠詞］父
                              （frame弧は 与える→父 が全幅を横断）
```
問題:
1. **主語が最後（父）に来る**ため、述語→主語の frame 弧が band 全体を横断し長く・追いにくい。
2. **動詞が中央**、項が左右に散る → frame 弧が中間 chip を跨ぎ、どの弧が主語/目的かを目で辿る必要がある。
3. **横軸が構造的意味を持っていない**（原文順＝Word Order と重複）。せっかくの横軸が情報を運んでいない。
4. **後置・非連続**の語順ノイズが構造理解に無関係に混入する。
5. **節間で位置が変わる**（surface 依存）ため、複数節の構造比較がしにくい。

⇒ 「原文順の維持」自体が、frame relation と role 対応の一目理解を阻害している。

## SF-15-B: レイアウト3案（6:37/6:38/6:39/6:51 で評価）

実データの band role（実測）:
- 6:37 δίδωσίν: [目的語 〜するもの][動詞★][間接目的語 私][主語 父]
- 6:38 御心: [role無 御心★][role無 ［冠詞］私の]（frame無）
- 6:39 この: [述部★][繋ぎ動詞][主語 …送る私][目的語 …最後の日]（referent: この→滅ぼす/立ち上がる）
- 6:51 〜である: [主語 私][繋ぎ動詞★][述部 …天下る]（S-VC-P＝既に自然順）

### 案A：focus 中心・横配置（focus-anchored linear）
focus を先頭に置き、関係先を frame スロット順で右へ。横軸＝「focus → その関係先」。
```
[動詞 与える★] → [主語 父] → [目的語 〜するもの] → [間接目的語 私]
```
- focus が明確・弧が短い。ただし role の位置が focus 依存で毎回変わり、節間比較しにくい。focus が項の時は「focus → その述語」。

### 案B：focus 中心・上下配置（radial/stacked）
focus を中央、項を role で上下左右へ。
```
            主語 父
             │
目的語 ── [与える★] ── 間接目的語
〜するもの            私
```
- 空間対応は直感的だが、**項が3つ以上（6:39/6:51）で破綻**、上下が**包含チャネルと紛らわしい**、mobile の2Dは縮退困難、grammar-tool 感が最も強い。

### 案C：focus 中心＋role別配置（canonical role lanes）＝**横軸＝正準 role 順**
横軸を **正準的な文法役割テンプレート順**（主語→動詞/繋ぎ→補語/述部→目的語→間接目的語→副詞的→role無は末尾）に固定。構成語をその役割位置へ置く。focus は色で強調。
```
主語        動詞          目的語        間接目的語
[父]    [与える★動詞]     [〜するもの]      [私]
          └─ frame弧(短・隣接) ─┘
```
- 主語が常に左・動詞が次…と**位置が固定**＝role を見ずとも構造が読める。frame 弧が**短く交差しない**。節間比較容易。role無 band（6:38 御心）は正準順が無いので**中立順（focus 先頭）**へ縮退。

### 評価

| 評価 | 案A | 案B | 案C(推奨) |
|---|---|---|---|
| focus が一目 | ◎ | ◎ | ○(強調で明確) |
| role↔chip 対応 | ○(位置可変) | ○ | ◎(位置固定) |
| frame が一目 | ○ | ◎ | ◎(短弧・隣接) |
| 包含と混同しない | ○ | △(上下と紛れる) | ◎(横=role/縦=包含) |
| 複数項で破綻しない | ○ | ✗ | ◎(レーン増設) |
| mobile 縮退容易 | ◎ | ✗ | ◎(1行→SF-14縮退) |
| grammar-tool 許容 | 中 | ✗(強) | 中(許容) |
| Reading UI として自然 | ○ | △ | ◎ |

## SF-15-C: 推奨 ＝ **案C（横軸＝正準 role 順）**

**中心の問いへの回答: Structure Flow の横軸は「正準的な文法役割順（normalized clause template）」にする。** 原文順は捨てる（Word Order が担う）。

理由:
- 「語順を捨ててよいなら何を見せるべきか」＝**役割配置**。主語が常に左…と固定することで、focus の項（主語/目的語/間接）が **role を読む前に位置で分かる**。
- frame 弧が隣接化し短く・交差せず、SF-14 の「focus↔target 一目」を更に強化。
- 包含（縦）/ frame（下弧）/ referent（上点線）/ role（横軸＝配置＋キャップ）の4チャネルが軸として分離。
- 原文の非連続・後置ノイズを排除し、節間で構造を同じ形で読める。

## John 6:37 具体 ASCII（案C・正準 role 順）

```
■ focus=δίδωσίν(動詞)
 所属するまとまり
  主語        動詞          目的語        間接目的語
 [父]    [与える]★動詞    [〜するもの]      [私]
           ╰──弧→父 / 弧→〜するもの / 弧→私（短・隣接・▸=項）──╯
 上位 [ …節… ]                         （縦線＝包含）

■ focus=ὃ(目的語)   … 原文順では2番目、正準順では目的語スロット
  主語     動詞      目的語         間接目的語
 [父]   [与える]  [〜するもの]★目的語   [私]
                   ╰ 弧→与える(述語) 1本 ╯     ← ὃ→πᾶν は描かない（Lowfat に無し）

■ focus=πᾶν(role無・親np=主語)  … 兄弟に role 無 → 中立順（focus 先頭）
```

6:38（frame/role 無）は中立順のまま role 統合のみ。6:39（referent 同文）は正準順＋referent 点線（band 折返し時は SF-14 通り注記へ縮退）。6:51（S-VC-P）は正準順＝ほぼ原文順で `主語 私 / 繋ぎ動詞 〜である★ / 述部 …天下る`。

## SF-14 から：維持するもの / 変更するもの

**維持**:
- 4チャネル（包含=帯＋上位縦線／frame=下・実線弧・▸／referent=上・点線弧／role）とその意味分離。
- frame は **Lowfat 明示 node-id 間のみ**。推論禁止。**ὃ→πᾶν 非描画**。文外/ゼロ非接続。
- role の帰属を偽らない（word 由来/unit 由来の区別）。
- mobile/折返し時の縮退（弧を消し SF-12 role キャップ＋短い注記）。
- focus 強調、包含（所属/上位）表示。

**変更**:
- **横軸: structural order（原文順）→ 正準 role 順**（normalized clause template）。並べ替えを許可（Word Order と役割分離）。
- role は「各 chip の真上ラベル」に加え **横軸の配置根拠** になる（role チャネルが軸へ昇格。他チャネルとは非混同）。
- frame 弧は正準順で **短く隣接化**（交差減）。役割は「弧が無くても role 位置で読める」補助へ。
- role を持たない band は **中立順（focus 先頭）** に縮退（正準テンプレを適用しない）。

## 実装フェーズ（SF-16）で確定する事項（本監査では決めない/コード不変）
- 正準 role 順の rank テーブル（copula 補語 p を vc 直後に置く等の細部）。
- 並べ替え時の frame 弧の再計算（隣接化後の level/矢頭）。
- role 無 band・部分 role band の中立順規則。
- 6:39 の巨大 band での referent 縮退閾値。
- 実ブラウザ検証（wide→420→360）。

**結論**: SF-15 推奨は **案C（横軸＝正準 role 順）**。本 SF-15 ではコードを変更しない。
