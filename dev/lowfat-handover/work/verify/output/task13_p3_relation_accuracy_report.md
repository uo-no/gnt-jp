## 4. 統語関係の正確性の判定

**判定: INCORRECT**

現在の RK 図が示す関係:
- `δηλώσας` → `ὑμῶν` (vo): 動詞が ὑμῶん を直接目的語として取る
- `ὑμῶν` → `ἀγάπην` (mod): ἀγάπην が ὑμῶん を修飾する

LOWFAT が定義する関係:
- `δηλώσας` の role=o は `DetNP{τὴν, ofNPNP{ὑμῶん, NpPp{ἀγάπην}}}` であり、意味的 head は `ἀγάπην`
- RK 慣習では: `δηλώσας` → `ἀγάπην` (vo)、`ἀγάπην` ← `ὑμῶν` (mod: 所有格修飾)

**エッジ方向が逆**: 現在は「ἀγάπην が ὑμῶん を修飾する」と示しているが、正しくは「ὑμῶν が ἀγάπην を修飾する」。

## 6. 根本原因

### 原因 A — B-3: phrase() hi 選択の誤り

`phrase(ks, x, y)` の head 語選択:

```javascript
let hi = ks.findIndex(k=>k.tagName==='w'&&!NONHEAD.has(A(k,'class')));
// NONHEAD = {det, prep, conj}
// ks = [ὑμῶν(pron), NpPp(wg)]
// ks[0] = ὑμῶν: class='pron' → NOT in NONHEAD → hi=0
```

`ks[0]` = ὑμῶν (class=pron) が NONHEAD に含まれていないため hi=0 が選ばれる。既存の補正（adj→noun 変換）はクラス `adj` にのみ適用され、`pron` には対応しない。

`ofNPNP` 規則では第一要素が属格修飾語、第二要素が主名詞句という構造を持つ。しかし `phrase()` の汎用 hi 選択ロジックはこの規則固有の語順を認識しない。

### 原因 B — D-2: rk-dy=602 による縦方向大幅分離

NpPp wg に `rk-dy=602` が設定されており、mods() での通常位置 (IND=30) に加えて 602px 下方に配置される。

```
ὑμῶん (head)  y=1950
↓ (IND=30 + rk-dy=602 = 632px)
ἀγάπην        y=2590  ← 通常より 602px 下
```

原因 A で ὑμῶん が head、NpPp が mod になった結果として、D-2 の rk-dy=602 が適用されている。原因 A が修正されれば D-2 の効果は消える（NpPp が head になるため mods() から外れる）。
