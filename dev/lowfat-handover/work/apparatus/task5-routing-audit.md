## Section 3：Plan C ルーティング設計詳細

### 経路決定ロジック（現在の比較実装）

```
条件: エッジ種別が 'mod' または 'dash'
     かつ |bx - ax| > 150
     かつ |by - ay| > 40
→ 垂直優先 L 字形: M ax ay  V by  H bx
   （source から垂直に target-y まで下降、次に水平に target-x まで移動）

上記条件を満たさない場合は既存直線（Plan A）を維持
```

### 各エッジ種別への影響

| エッジ種別 | Plan C の影響 | 理由 |
|---|---|---|
| `mod`（修飾線・斜め） | 条件を満たす場合 L 字形に変化 | 折り返し後の長距離修飾接続が対象 |
| `dash`（グループ間点線） | 条件を満たす場合 L 字形に変化 | 折り返しグループへの接続が対象 |
| `cont`/`sv`/`vo`/`vp`（水平リンク） | **変更なし** | 通常は dy≈0 のため条件不成立 |

### 閾値の妥当性

現在の閾値 `|dx|>150 AND |dy|>40`:

- `|dx|>150`: 通常の語間距離（約 40-80px）では発動しない。グループが少なくとも 2-3 語分以上横移動した場合のみ対象。
- `|dy|>40`: 同一行内の語句間（dy≈0-18）では発動しない。明確に別行（行間 ≈ 36px）に移動した場合のみ対象。

典型的な「1画角分の折り返し」（例: Δx ≈ 400-800）ではこの閾値は適切に動作する。

### 極端ケースの残存問題

Colossians Δx ≈ 2204、Luke Δx = 2771 のような極端な移動では:
- L 字形でも水平区間が 2000px 以上となり、依然として図全体を横断する。
- 「まず垂直に下降し、次に水平移動」という視覚的な追跡可能性は向上するが、画面内に始点・終点を同時に表示できない問題は残る。

→ **極端な折り返し距離は、ルーティング変更だけでは解決できない**。運用上の制約（折り返し距離の目安を示す UI ガイド等）が別途必要。

### Plan A / B / C 評価

**Plan A（直線・現状）**  
- 現時点で機能しているがレイアウト編集後は接続線が追跡困難になる。折り返しを活用した読書には不向き。
- VERDICT: 短距離（Δx < 200程度）では許容範囲。長距離折り返しでは問題あり。

**Plan B（視覚的弱化）**  
- 接続線を目立たなくすることで「見なくてもよい情報」として扱う設計。
- 問題: 構文上の接続情報を視覚的に軽視させることは、原著者の意図追跡という First Principle に逆行する可能性がある。
- 実装コスト: 最小（~3行）。
- VERDICT: 暫定措置としては使えるが推薦しない。接続情報を弱化するのではなく、追跡しやすくする方向が適切。

**Plan C（L 字形ルーティング）**  
- 「まず垂直に下降、次に水平移動」で読者が線を視覚的に追いやすくなる。
- 典型的な折り返し距離（Δx ≈ 400-800）では有効。
- 極端なケース（Δx > 2000）では限界がある。
- スクリーンショットでの L 字レンダリング確認: **NOT VERIFIED**（今回の比較では適切な zoom ビューが取得できなかった）
- 実装コスト: 低（pd() 内 ~10行変更）。
- VERDICT: **推薦**。ただし実装前に pd() の FROZEN 状態を確認し、実装後にエルボー折れ点を正面から撮影した検証スクリーンショットを必ず取得する。

### 最小実装計画（Plan C）

**変更箇所**: `app/rk-diagram-m3.html` 内の `pd()` 関数

**実装内容（概略）**:
```javascript
function pd(ed) {
  const {a, b, type} = ed;
  const dx = b.x - a.x, dy = b.y - a.y;

  // mod / dash エッジの長距離折り返しに L 字形を適用
  if ((type === 'mod' || type === 'dash') &&
      Math.abs(dx) > 150 && Math.abs(dy) > 40) {
    return `M ${a.x} ${a.y} V ${b.y} H ${b.x}`;
  }

  // 既存の直線処理（変更なし）
  // ...
}
```

**事前確認事項**:
1. `pd()` が FROZEN 扱いかどうかを確認
2. `cont`/`sv`/`vo`/`vp` エッジが L 字形条件を満たさないことを静的確認
3. 実装後に接続線の折れ点を画面中心に捉えたスクリーンショットを取得（現行の routing_compare.js を修正してズーム位置を接続線上に合わせる）

**Regression 対象**:
- grp_dx_test.js（42件）: rk-dx/rk-dy 動作に影響がないことを確認
- Colossians 主節内の水平 cont/sv/vo エッジが直線を維持することを確認

**変更種別**: `UX`（表示整形のみ、データ・構造・L-0 への影響なし）
