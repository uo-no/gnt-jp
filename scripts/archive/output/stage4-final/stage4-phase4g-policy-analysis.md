## 1. G863 ἀφίημι — 現在: `赦す`

### 1.1 問題の所在

母集団 143件のうち、30件サンプリング済み。  
結果: **9件（30%）が赦免文脈（赦す ✓）、21件（70%）が非赦免文脈（赦す 不適）**。

非赦免文脈をさらに二分すると:
- **Cluster B（去る / 放棄）**: 10件 — 離れる・後にする・捨てる・疎かにする
- **Cluster C（許可 / 任せる）**: 11件 — させる・〜してよい・黙認する

母集団 143件に外挿すると:
- Cluster A（赦免）: ~43件（30%）
- Cluster B（去る）: ~47件（33%）
- Cluster C（許可）: ~53件（37%）

ただしこれは点推定であり、未サンプルの113件に確認誤差がある。

### 1.2 形態と Cluster の相関

受動態（V-API/FPI/PPI/RPI）→ **ほぼ Cluster A**  
例外: LUK 17:35 ἀφεθήσεται（V-FPI-3S）en=left — Cluster B

能動態（命令・分詞・直説法）→ **B または C が多数**  
例外: LUK 23:34 ἄφες（V-2AAM-2S）en=forgive — Cluster A  

受動態か能動態かは形態コードで判別可能。しかし例外が存在するため、形態のみでは一意に分類できない。

### 1.3 JA1955 の表現パターン

JA1955 では ἀφίημι に複数の訳語が使われる（確認した用例から）:
- Cluster A: 「赦す」「赦される」（受動）
- Cluster B: 「去る」「後にする」「置いていく」「疎かにする」
- Cluster C: 「させる」「〜してよい」「許す」「黙認する」

JA1955 は文脈ごとに訳語を変えている。Reading Japanese の原則（構造的意味の表示）とは異なるアプローチ。

### 1.4 ポリシー選択肢

**オプション A（現状維持）**: `赦す` を全用法に適用  
- 影響: Cluster B・C の読者は `赦す` から正しい文脈意味を読み取れない
- 利点: 語彙の統一性を保つ。訳ではなく語根表示として割り切れる
- 問題: 「平和を残す（JHN 14:27）」「羊を見捨てる（JHN 10:12）」「子を来させる（MAT 19:14）」に `赦す` は誤解を招く

**オプション B（クラスター別ラベル）**: Cluster A / B / C で異なる日本語を適用  
例案:
- Cluster A: `赦す`（forgive/pardon）
- Cluster B: `去る`（leave/abandon）— ただし「疎かにする」「残す」を含むため多様
- Cluster C: `許す`（let/allow/permit）— ただし「黙認する」「離縁する」も含む

複数の候補が必要。形態コードで自動分類する場合、例外処理が必要。

**オプション C（受動 / 能動の二分類）**  
- 受動態: `赦される`（赦免の受動形）
- 能動態: `放す`（release / let go — leave と allow の共通概念）

形態コードで機械的に判別可能。ただし能動態 forgive（LUK 23:34 等）と能動態 leave（MAT 4:20 等）を同じ `放す` にする妥当性に疑問が残る。

**オプション D（多義複合表示）**  
日本語: `赦す・去る`（ハイフン・スラッシュで多義を示す）  
例: `赦す / 去る / 許す`（全クラスターを列挙）  
メリット: 訳語選択をしない（Reading Japanese 原則に最も近い）  
デメリット: 情報量過多、読書支援として機能するか不明

**オプション E（弁別的トークン個別修正）**  
Cluster B・C のトークンのみ個別に `token.japanese` を修正する（語彙レベルの一括変更はしない）。  
例: MAT 4:20 ἀφέντες → `去る`、MAT 19:14 Ἄφετε → `許す` 等  
メリット: 最も精緻。デメリット: bible_data の大規模修正（143件分の確認が必要）

### 1.5 影響範囲

- G863 母集団: 143件
- Cluster B + C 推定: ~100件（70%）
- bible_data 変更が発生する場合の対象: 最大 100件
- 読書面への表示変更: `token.japanese` を使うすべての表示パス

### 1.6 決定前の確認推奨事項

- 受動形の全件スキャン（約 40件）: Cluster A の割合を実測する
- Cluster B・C の境界例（JHN 14:27: "平和を残す"）の扱いを確定する
- `reading-engine.js` の Phase 4（lexicon）が `token.japanese` を使うか、独自 lexicon を使うかを確認する
- 修正後の回帰テスト範囲を確定する

## 2. G1210 δέω — 現在: `縛る`

### 2.1 問題の所在

サンプル 24件の内訳:
- δέω 正規形（bind/tie）: **6件（25%）**
- δεῖ 形（must/ought/necessary）: **17件（70.8%）**
- δέομαι 語根混入（HOLD）: **1件（4.2%）**

母集団 138件に外挿すると:
- δέω 正規形: ~35件（25%）
- δεῖ 形: ~97件（70%）
- 不確定（δεόμαι等含む）: ~6件（5%）

### 2.2 δεῖ の Strongs 分類問題

Strong's Exhaustive Concordance では δεῖ に **G1163** を割り当て、δέω（G1210）と区別している。  
ただし一部の参考文献は δεῖ を δέω の派生形として G1210 に含める（語源的連関）。

bible_data の選択は G1210 統合。これがデータの設計判断であれば、`縛る` は G1210 全体を表すラベルとして一応整合する。

しかし `縛る` は「〜しなければならない」の意味を読者に伝えない。語源的表示（etymological representation）として解釈しても、読書支援として機能しない。

### 2.3 ポリシー選択肢

**オプション A（現状維持）**: `縛る` を全用法に適用  
- 根拠: G1210 の語源的表示（δεῖ は「縛る = 義務付ける」から派生）
- 問題: 読者は δεῖ の文脈で `縛る` から義務を読み取れない

**オプション B（bible_data の G1163/G1210 再分類）**  
δεῖ 形を G1210 から G1163 に再割当てし、G1163 に独立した ja ラベルを設定する。  
例: G1163 → `〜しなければならない`（または `必要`）  
G1210 → `縛る`（δέω 正規形のみ）  
メリット: Strongs 標準に準拠、読書支援として機能する  
デメリット: bible_data の大規模修正（~97件の strong 変更）、既存処理への影響

**オプション C（G1210 の ja を多義表示に変更）**  
`縛る・必要` または `縛る / 〜すべき` を G1210 の ja にする。  
メリット: bible_data の strong 変更不要、読者に両義を示せる  
デメリット: 多義表示が Reading Japanese の原則と整合するか要確認

**オプション D（トークン個別修正）**  
δεῖ 形のトークン（~97件）の `token.japanese` を個別に `〜しなければならない` に修正する。  
δέω 正規形は `縛る` を維持。  
メリット: 形態コード（V-PAI-3S / V-PAN）で δεῖ 形を機械的に特定可能  
デメリット: bible_data 修正の規模（~97件）

### 2.4 形態コードによる δεῖ 形の特定可能性

δεῖ = V-PAI-3S（現在能動直説法 3人称単数）または V-PAN（現在能動不定詞）  
δέω 正規形 = V-AAP-NPM（アオリスト能動分詞）、V-RPP-NPN（完了受動分詞）等  
ROM 1:10 δεόμενος = V-PNP-NSM（現在中動分詞）

V-PAI-3S をもつ G1210 トークンは「ほぼすべて δεῖ」の可能性が高い。機械的一括修正の候補。

### 2.5 影響範囲

- G1210 母集団: 138件（δεῖ 形 推定 ~97件）
- bible_data 変更対象（オプション D）: 最大 100件
- G1163 追加が必要な場合: G1163 の全母集団スキャン（未知）

## 3. G2919 κρίνω — 現在: `裁く`

### 3.1 問題の所在

サンプル 24件の内訳:
- judicial/condemn: **20件（83.3%）**
- decide/determine: **4件（16.7%）**

問題規模は G863・G1210 と比べて小さい。ただし確認された「決める」用例は一貫してシナゴーグ外の個人意思決定文脈。

### 3.2 ポリシー選択肢

**オプション A（現状維持）**: `裁く` を全用法に適用  
- 根拠: 83.3%は正確。`裁く` の語義範囲（"determine/resolve"）に「決める」を含む解釈は可能
- 問題: 2CO 2:1「悲しみをもって行かないと**裁いた**」、ACT 20:16「素通りすると**裁いた**」は不自然

**オプション B（単一 RC 処理）**  
decide/determine の用例 4件を個別修正する。  
例: ἔκρινα（1S）/ κεκρίκει（LAI-3S）の特定 refs のみ `判断する` に変更。  
メリット: 最小侵襲。4件のみ変更。  
デメリット: 語彙の統一性が崩れる（same Strong が2つの ja を持つ）

**オプション C（多義表示）**  
`裁く・判断する`  
メリット: 修正不要  
デメリット: 文字数増加、視覚的な重さ

### 3.3 母集団推定

- G2919 母集団: 115件
- decide/determine 用例推定: ~19件（16.7%）
- judicial 用例推定: ~96件（83.3%）

影響規模は G863・G1210 の約1/5。
