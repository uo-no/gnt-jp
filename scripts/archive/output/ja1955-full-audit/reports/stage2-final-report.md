## 3. 人的確認件数（自動分析）

**230件全件を分析完了**。

「人的確認」の定義: 各トークンについて以下の自動検証を実施した。

1. **クロストークン衝突検出**: 同じ節内に同じJapaneseラベルを持つ別トークンが存在するか確認
2. **漢字衝突検出**: kanji matchの場合、抽出漢字が別トークンのラベルにも含まれるか確認
3. **多重出現検出**: 節テキスト内に同一語が複数回出現するか確認
4. **語義的リスク評価**: 高頻度機能語・代名詞指示対象の文脈依存性確認
5. **コンテキスト確認**: 前後±3トークンのギリシャ語文脈を取得・記録

### 5.2 誤判定の根本原因

全35件の誤判定に共通する原因: **`duplicate_label` 問題**（全35件に発生）

```
同じ節内に同じ Japanese ラベルを持つ別のトークンが 1件以上存在する
→ verseText に該当語が含まれることは確認できるが、
  どのトークンがその語に対応するかを containsBase() は判別できない
```

#### 問題の具体例

**G2532 (そして) — 1296件**
```
JAS 1:11!8, !12, !17 の3トークンすべてに japanese="そして"
JA1955節テキストに「そして」が1回だけ出現
→ 3トークンとも containsBase()=true で現状維持に分類
→ 実際に対応するのは1件のみ可能性が高い
```

**G5213 (あなたがた) — 508件**
```
1TH 1:3のような節に ὑμῶν(G5216) / ὑμῖν(G5213) / ὑμᾶς(G5209) が同時登場
すべて「あなたがた」とラベルされ、すべてcontainsBase()=true
JA1955では異なる格の変化は必ずしも区別されない
```

**G846 (彼ら) — 989件**
```
αὐτός/αὐτή/αὐτοί が同一節に複数登場する場合、
JA1955の「彼ら」が特定のどのトークンに対応するか不確定
```

#### 問題タイプ別件数（35件中）

| 問題タイプ | 件数 | 説明 |
|-----------|------|------|
| duplicate_label | 35 | 同じ節内に同じラベルが複数トークンに存在（主原因） |
| multi_occurrence | 17 | 節テキスト内に同一語が2回以上出現 |
| pronoun_referent | 14 | 代名詞の指示対象が文脈依存 |
| high_freq_function_word | 7 | 高頻度機能語（そして、神、主等）の文脈依存性 |

## 8. 自動判定ルールの改善候補

### 8.1 最優先: `containsBase()` のクロストークン検証

**現行の問題**:
```javascript
function containsBase(verseText, japaneseBase) {
    // 節テキスト内に語が存在するかのみ確認
    // どのトークンに対応するかを検証しない
    if (verseText.includes(clean)) return true;
    ...
}
```

**改善案**:
節内の全トークンを走査し、「このトークンのJapanese が、他のトークンのJapanese で既にカバーされていないか」を確認するロジックを追加する。

```javascript
// 節内に同じJapaneseラベルが複数ある場合、
// 現状維持ではなく「要確認」に分類する
function hasUniqueMapping(token, verseTokens) {
    const sameLabel = verseTokens.filter(t =>
        t.tokenId !== token.tokenId && t.japanese === token.japanese
    );
    return sameLabel.length === 0;
}
```

### 8.2 高頻度代名詞・接続詞の特別扱い

以下のStrongは `containsBase()` による自動判定が構造的に信頼できない:

| Strong | Japanese | 現状維持 | 理由 |
|--------|----------|---------|------|
| G5213 / G5209 / G5210 / G5216 | あなたがた | 計1,820件 | 複数の格変化形が同一節に存在 |
| G2532 | そして | 1,296件 | 接続詞が節内に複数存在 |
| G846 | 彼ら | 989件 | 複数形が節内に複数存在 |
| G2316 | 神 | 1,295件 | 節内2回以上出現の可能性 |

これらは「現状維持」ではなく「要確認（構造的）」として別カテゴリで管理することを推奨する。

### 8.3 kanji matchの改善

kanji matchは「節テキストに漢字2字以上が含まれる」という判定だが、その漢字が別の熟語の一部として現れている可能性を排除できない。

**改善案**: kanji matchは「現状維持」ではなく「概ね妥当（要確認）」とし、人的確認の優先度を高く設定する。

## 9. Stage 3へ進む前に解決すべき課題

### 9.1 必須（BLOCKER）

**課題1**: **高頻度代名詞4グループ（ὑμεῖς各格）の追加検証**
- 対象: G5213, G5209, G5210, G5216（計1,820件）
- 問題: FP率が50〜86%と高く、現状維持として扱うことが困難
- 対処: 「構造的要確認」として別分類し、自動検証スコープから除外するか、追加サンプリングで実態確認

**課題2**: **G2532 (そして) 1,296件の追加検証**
- 問題: n=4のサンプルでFP75%（信頼性低）— 追加サンプリングが必要
- 対処: G2532専用サンプル30件以上を取得し、実FP率を再推定

### 9.2 推奨（Stage 3の品質に影響）

**課題3**: **`containsBase()` のクロストークン検証機能の追加**
- 影響: 将来の自動監査の信頼性向上
- 対処: 8.1の改善案を `audit-ja1955-nt-wide.cjs` に実装

**課題4**: **「現状維持」の再分類**
- 現行: 1件でも `containsBase()=true` なら現状維持
- 改善後: 節内で唯一の対応トークンである場合のみ現状維持、複数ある場合は「構造的要確認」
