## 2. 代名詞4 Strong（ὑμεῖς各格）1,637件の再分類

### 件数注記

現状維持セット内での実際の件数は **1,637件**（旧見積もり1,820件は現状維持以外も含む件数の参照ミス）。

| Strong | 意味 | 現状維持件数 |

| G5216 (ὑμῶν) | あなたがた（属格） | 521 |
| G5209 (ὑμᾶς) | あなたがた（対格） | 390 |
| G5210 (ὑμεῖς) | あなたがた（主格） | 218 |
| **合計** | — | **1,637** |

### 再分類結果

| 分類 | 件数 | 割合 | 定義 |
|------|------|------|------|
| `structural_review_required` | 970 | **59.3%** | 同じ節内に同じラベルを持つ別トークンが存在。containsBase()では対応を一意に特定できない |
| `explicit` | 667 | 40.7% | 節内で唯一の「あなたがた」トークン。JA1955に直接対応確認可能 |
| `none` | 0 | — | — |
| `uncertain` | 0 | — | — |

### 主な発生パターン

**パターンA（最多）: 節内に複数の格変化形が同時登場**
```
例: 同一節内に ὑμεῖς(G5210) + ὑμῶν(G5216) + ὑμῖν(G5213) → 全員「あなたがた」
JA1955: 「あなたがた」を数回使用するが、各格形のどれに対応するかは別問題
```

**パターンB: 同一格形が節内に複数登場**
```
例: ὑμῶν(G5216) が節内に2箇所 → 両方「あなたがた」ラベル
JA1955に「あなたがた」1回 → どちらに対応するかが不確定
```

### 解釈上の注意

`structural_review_required` は「訳語が誤っている」を意味しない。「あなたがた」はほぼ確実に正しい訳語である。ただし **自動検証によって対応が確認できた状態ではない**。

Stage 3への引き継ぎ: 970件は「自動検証不能」として記録。訳語の正確性は別途文脈確認が必要だが、同一書の他節での対応パターンから帰納的に推定可能。

## 6. 自動判定ルールの改善方針

コードは変更しない。設計案のみ比較する。

### 改善案 A: クロストークン衝突検出の追加

**現行問題**: `containsBase(verseText, japanese)` が節テキスト内に語が存在するか確認するが、どのトークンが対応するかを判別しない。

**改善案**:
```
現状維持 の条件を以下に変更:
(1) containsBase(verseText, japanese) = true
かつ
(2) 同じ節内に同じ japanese ラベルを持つ別トークンが存在しない
(3) 節テキスト内に該当語の出現が1回のみ
```

| 評価 | 内容 |
|------|------|
| 偽陽性削減効果 | 高（duplicate_labelの主因を解消） |
| 実装上の問題 | 節内トークンの全ロードが必要（現行よりO(n)負荷増） |
| 副作用 | 一部の legitimate な現状維持が「要確認」に移動（偽陰性増） |
| 推定効果 | 32,317件中 ~2,000件が「現状維持」から「structural_review_required」へ再分類 |

### 改善案 B: Strong別 自動判定ブラックリスト

**改善案**: 構造的に自動判定が不十分なStrongをリスト化し、これらは自動判定の対象外とする。

```
STRUCTURAL_REVIEW_REQUIRED_STRONGS = ['G5213','G5209','G5210','G5216','G2532','G846',...]
```

| 評価 | 内容 |
|------|------|
| 偽陽性削減効果 | 高（特定Strong全件に適用） |
| 実装上の問題 | ブラックリストの網羅性に依存。他のStrongでも同様の問題が起きる可能性 |
| 副作用 | legitimate な explicit 対応も要確認に入る（670件 / 1,637件） |
| 推定効果 | G5213/G5209/G5210/G5216/G2532 の計 2,933件が automatic verification から除外 |

### 改善案 C: 位置情報を用いた対応確認（長期的改善）

**改善案**: JA1955テキストと bible_data トークンの位置的対応（文の構造マッチング）を導入。

| 評価 | 内容 |
|------|------|
| 偽陽性削減効果 | 非常に高（根本的解決） |
| 実装上の問題 | JA1955は訳語で文構造が異なるため、1対1の位置マッピングは困難。実装コスト大 |
| 副作用 | 開発工数が大きく、Stage 2の範囲外 |
| 推定効果 | 理想的には全件を精度高く検証可能 |

### 推奨方針

**短期（Stage 3前）**: 改善案 B（Strongブラックリスト）を採用。実装が簡潔で、主要な問題Strongをカバーできる。

```
AUTOCHECK_EXCLUDED_STRONGS = [
    // ὑμεῖς 各格（あなたがた）
    'G5213', 'G5209', 'G5210', 'G5216',
    // 高頻度接続詞（同一節内重複多発）
    'G2532',
    // 高頻度代名詞（同一節内重複多発）
    'G846',
]
```

これらのStrongのトークンは「現状維持」ではなく「structural_review_required」として別管理する。

**中期（Stage 3後）**: 改善案 A（クロストークン衝突検出）を実装。全トークンに適用可能な汎用的解決策。
