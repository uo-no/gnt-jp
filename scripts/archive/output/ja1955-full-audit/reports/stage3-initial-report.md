## 2. 追加ブラックリスト候補（Stage 3 発見）

σύ（あなた）単数形 4格変化がすべて SR率 >40% であることが判明した。

| Strong | 形 | pool内件数 | SR率 | explicit率 |
|--------|-----|-----------|------|------------|
| G4675 | σοί（与格） | 389 | **75.3%** | 24.7% |
| G4571 | σε（対格） | 165 | **71.5%** | 28.5% |
| G4771 | σύ（主格） | 152 | **55.3%** | 44.7% |
| G4674 | σοῦ（属格） | 17 | **41.2%** | 58.8% |
| **σύ合計** | | **723** | — | — |

**構造的原因:** ὑμεῖs と同じ duplicate_label 問題。σύ の格変化形が同一節内に複数登場すると `containsBase()` はどのトークンに対応するか特定できない。

**初回サンプル（S4: 10件）での確認:**
- `LUK 7:50!8` `ACT 2:35!6`: G4675「あなた」が同節内に2件 → SR
- `TIT 3:15!2` `MAT 19:21!11`: 節テキストに「あなた」が2回出現 → uncertain
- `1CO 15:36!2` `EPH 6:2!4` 等 6件: 単独出現 → explicit

**判断必要事項:** 本候補を正式にブラックリストに追加するかどうかはユーザー判断。
- 追加した場合: Stage 3 pool が 723件減少 → 27,496件
- 追加しない場合: Stage 3 内で individual-check フラグを付けて処理

## 3. Stage 3 サンプリング設計

### 3.1 設計原則

「頻度の高い語から機械的に処理する」のではなく、**語の意味機能・訳し方・文脈の多様性**を考慮した6層設計。

### 3.2 層定義

| 層 | 名称 | 代表 Strong | pool | 初回 |
|----|------|-------------|------|------|
| S1 | 神的固有名詞 | G2424・G5547 | 1,423 | 5 |
| S2 | 神的称号 | G2316・G2962・G3962・G5207・G4151 | 3,065 | 15 |
| S3 | 人物関連名詞 | G444・G80・G3101・G1135・G5043 | 1,338 | 10 |
| S4 | σύ単数代名詞 | G4675・G4571・G4771・G4674 | 723 | 10 |
| S5 | 高頻度名詞・形容詞 | G3956・G3056 等 | 1,843 | 10 |
| S6 | 低頻度 Strong（<20件） | 多様 | 6,741 | 10 |
| **合計** | | | | **60** |

### 3.3 各層の対応分類と留意点

**S1 神的固有名詞（イエス・キリスト）**
- リスク: 低。固有名詞は日本語表記が安定。
- 期待: explicit 率 > 80%

**S2 神的称号（神・主・父・子・霊）**
- リスク: 中〜高。G2316(神)は節内複数出現が多い（quickSR=70%, 実サンプル=20%）。
- 留意: 同節に「神」「父」「子」「霊」が混在する文脈での duplicate_label に注意。

**S3 人物関連名詞（人・兄弟・弟子等）**
- リスク: 中。複数人物が列挙される節で SR 発生。
- 例: `COL 1:28`「人」が同節内に3件

**S4 σύ単数代名詞**
- リスク: 高。75% SR（G4675）。
- ブラックリスト追加が推奨されるが、Stage 3 内で検証継続。

**S5 高頻度名詞・形容詞（すべての等）**
- リスク: 中。G3956(すべての)はquickSR=67%だが実サンプルでは explicit が多い。
- 留意: 「すべての者」「すべての人」等が同節内に混在するケースを要確認。

**S6 低頻度 Strong（<20件）**
- リスク: 多様。ロングテールのため書巻・文脈の多様性が高い。
- 意義: 高頻度語に偏らないサンプリングで全体像を補完。

## 6. Stage 3 処理上の制約

以下の制約はすべての Stage 3 処理に適用される。

1. **Strong番号だけで一括判断しない** — 同一 Strong でも文脈によって対応が異なる
2. **同一節内の重複表現を確認する** — duplicate_label を個別に検出する
3. **JA1955との対応を explicit / implicit / none / uncertain で記録する**
4. **自動判定と人的確認を区別する** — このサンプルはすべて自動分析
5. **サンプルから全件の正確性を断定しない** — n=60 は設計確認用
6. **聖書JSONと承認済みデータは変更しない**

## 8. 判断を要する事項

### 8.1 σύ単数形 追加ブラックリスト化

**状況:** G4675(75%), G4571(72%), G4771(55%), G4674(41%) すべてで SR率 >40%。
ὑμεῖs と同じ duplicate_label 問題が確認された。

**オプション A: ブラックリスト追加**
- Stage 3 pool: 28,219 → 27,496 件（△723）
- 723件すべてが「精査なしに信頼不可」として管理される

**オプション B: Stage 3 内で個別 SR フラグ処理**
- 現 S4 層（10件サンプル）を継続
- SR=2, uncertain=2, explicit=6 の比率が維持されるかどうかを次サンプルで確認

### 8.2 G2316(神) quickSR=70% vs 実サンプルSR=20% の乖離

quickSRRate 関数は pool の先頭30件（書巻偏りあり）を使用。
実サンプルは書巻分散あり。

**推定原因:** 特定書巻（たとえばヨハネ文書）では「神」の多重出現が多いが、
他書では単独出現が多い。全体 SR 率は書巻分布により大きく変動する可能性がある。
