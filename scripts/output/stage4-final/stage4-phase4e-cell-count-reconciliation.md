## 3. 差異の原因分析

### 3.1 final-report.md §3 合計行の算術エラー

per-Strong の個別値は実データと完全一致する。合計行のみが誤っている。

**セル総数の差（547 vs 544）:**

final-report.md の列値を加算:
40+11+54+44+18+5+32+18+46+34+27+39+38+27+4+42+4+4+55+5 = **547**

しかし v3 JSON の per-Strong 総セル数は:
40+11+**50+50**+18+5+**27**+19+**38**+34+27+39+37+**28**+4+**48**+4+4+**56**+5 = **544**

差異のある Strong:

| Strong | report 値 | v3 実測 | 差 |
|--------|---------|--------|---|
| G1096 | 54 | 50 | −4 |
| G1325 | 44 | 50 | +6 |
| G1831 | 32 | 27 | −5 |
| G2064 | 46 | 38 | −8 |
| G2983 | 38 | 37 | −1 |
| G3004 | 27 | 28 | +1 |
| G3708 | 42 | 48 | +6 |
| G4160 | 55 | 56 | +1 |
| 列合計 | 547 | 544 | −3 |

報告書は v2 ドライランから読み取った値を手動で転記・集計したが、8 Strongs で転記エラーが生じ合計が 547（実際は 544）になった。

**singleton の差（123 vs 110）:**

per-Strong の小セル数（n=1）を再加算:
6+1+13+13+5+0+8+2+7+4+8+7+13+7+0+9+0+0+6+1 = **110**

報告書の合計行は 123 と記載しているが、列値を加算すると 110 になる。これは**合計行の単純な算術エラー**であり、per-Strong の値は正しい。

**大セル（n≥2）の差（424 vs 434）:**

- もし合計行が正しければ: 547 − 123 = 424
- 実データ: 544 − 110 = 434

誤った合計行の 2 つのエラー（+3 と +13）が打ち消し合った結果、見かけ上の大セル数の差が 10 になった。

### 3.2 final-audit-addendum.md への影響

Phase 4d 最終監査補足書に記載した「434 大セル中 244 採用ゼロ（56.2%）」は **実データに基づいており正しい**。v3 JSON から直接集計した値であり、final-report.md の誤った合計行には依存していない。
